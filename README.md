# Agentic-Evo

Private research repository for Agent Runtime Intelligence and the study of autonomous, continual Agent self-evolution.

The project is not a Codex plugin or a Codex-specific optimization system. The user is the only host; Codex is currently a research tool and one possible execution surface. The research target is a coding-agent-, model-, and project-independent Autonomous Agent Evolution System bound to one user lineage.

## Current status

**Pre-Genesis.** The portable `Trusted State + Body + Runtime + Witness process rehearsal + Codex Adapter` slice exists and is tested, but it is not installed globally and no formal Root has been created. Identity, Head, sessions, evidence, and local checkpoints commit in one SQLite transaction. On Windows, the foreground rehearsal now proves four partial native components: Job Object process-tree fencing; an account-bound public named pipe with explicit DACL and peer-SID verification; a suspended restricted Low-Integrity Body whose actual child token is re-queried; and an explicit inherited anonymous-pipe pair carrying a strictly sequenced Body-initiated lineage rehearsal. Boot, command, response, and stop writes are deadline-bounded, and accepted results must equal the authoritative Witness response. An internal supervisor-stop joint now establishes one admission cutoff, rejects preconnected requests that were not admitted before it, closes the registered-active transport snapshot through one raw-close owner each, and waits for admitted work to quiesce; the service loop then closes any accept/register-race transport, joins workers, retires the Body/lease, releases the singleton, and permits same-home restart. The stop path itself creates no Root, Head, Authority, or evidence transaction, although work admitted before the cutoff may still commit exactly once and its caller may see an unknown outcome after EOF; stop is not exposed as public Off. On Windows, the full repository passes 123/123 tests with `ResourceWarning` treated as an error; WSL Ubuntu discovers the same 123 tests, passes 108, and explicitly skips 15 Windows-only contracts. These facts still do not create a distinct installed Body principal, make the same-account SID a `HostPresence` proof, authenticate the separate Off endpoint, or establish `agent_self_authored`. The system is not SCM-installed; `native_security_verified=false` and `ready_to_install=false`. The next native item is an SCM-managed Witness principal with service-owned protected state and an attack-tested reversible install chain.
